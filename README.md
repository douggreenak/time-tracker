# TimeTrack — time log and customer invoicing for Apex Engineering

This app replaces the `2026_APEX BILLING.xlsm` workbook. People log time the way the workbook's **TIME SUMMARY** sheets do, and **Billing** builds one invoice per customer the way the workbook's macro does.

Built for **Vercel** + **Neon Postgres** (or an embedded Postgres locally). Next.js 14 App Router, Drizzle ORM, Tailwind.

## What it does
* **Timesheet** — one row per entry: date, customer, hours (tenths), description, lump sum, parts, contract/PO, billable, invoiced. Weeks collapse (current week open). The **Hours calculator** is the workbook's *HOUR DIFFERENCES* sheet (military start/end, minus gaps, plus a block, rounded to 0.1 h).
* **Billing** — pick a date range and customers (the *MACRO DATA* sheet: last invoice date, "new hours?"). *Create invoices* gives, per customer, the macro's layout: labor table (DATE, CUSTOMER, HOURS, TASK, PERSONNEL, RATE, TOTAL), editable PARTS table (qty × unit cost), a per-person SUMMARY, `PARTS TOTAL` and `INVOICE AMT. DUE`. Download **Excel** (one sheet per customer, live `SUMIF` formulas, one landscape page each), **Print**, or **Mark as invoiced** (saves the invoice and flags its time so it isn't billed twice). Invoice history can be re-downloaded or undone (accountants/admins).
* **Data** — *Customers*, *Lump sum*, *Other* and *Held time* (the workbook's LUMP SUM, OTHER and HELD TIME sheets).
* **Team** — people and roles, plus each person's **billing rate** (default $250, the workbook's only rate).
* **Import & saves** — import any year's workbook (adds time back to its original dates and skips what is already here). The app also saves a full-data spreadsheet each month and a yearly spreadsheet in the same layout (first use of each month / January), ready to download or import again.
* **Backup** (admin) — JSON export/restore.

Billable, not-held, not-yet-invoiced time is invoiced at `hours × the person's rate`. Lump-sum entries list on the invoice at $0 labor (price them from the Lump sum list). Rates are copied onto saved invoices, so changing a rate never alters history.

## Run it
```bash
npm install
npm run dev          # http://localhost:3000, embedded Postgres in ./.data/pglite, demo data loaded
npm run test:e2e     # Playwright, throwaway in-memory database
```
Demo data is built from the workbook (`src/db/workbook-demo.json`, generated by `scripts/build-demo-fixture.py`): 263 entries, 743.5 h, 43 customers. Every demo password is `demo1234`. Set `ENABLE_DEMO_DATA=false` for a blank start. See `SETUP.md` for Neon and Vercel, and `ARCHITECTURE.md` for the design.
